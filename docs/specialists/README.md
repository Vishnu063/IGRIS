# Specialist capabilities

Step 27 adds inert development role metadata and strict task/output contracts:
frontend, backend, mobile, AI and DevOps. They are IGRIS-owned minimal definitions,
not copied upstream prompt bodies. Recommendations select metadata only.

Each role accepts one declared task kind and bounded supplied text. It produces
proposal/checklist data with zero tool permissions. Contract fixtures are labeled
simulated and cannot report executed actions. No LLM, plugin, SDK, subprocess,
network client, file write, paid service or separate Agent Builder is activated.
Output schemas reject commands, permission fields and unrecognized keys.
Real specialist competence and model connections remain unverified. Step 30 will
add an approval-gated fixture execution boundary; current fixtures are test data,
not an unapproved live agent API. General execution permissions remain Guardian's.
